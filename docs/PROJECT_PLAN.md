# PromptGuard Project Plan

## Problem
Users often give LLMs vague, underspecified prompts. Poor prompts can lead to responses that are less relevant, less complete, inconsistent, or more likely to contain unsupported claims. PromptGuard studies whether systematic prompt engineering can improve response quality.

## Success criteria
- Analyze a prompt using measurable dimensions.
- Recommend at least one appropriate prompt-engineering technique.
- Produce an optimized prompt without changing the user's intent.
- Generate both original and optimized responses.
- Evaluate both responses using the same criteria.
- Demonstrate measurable improvement on a fixed test set.

## Report structure
The course sample report recommends 14 sections: Problem Statement; Objectives and Scope; Solution and Features; Tech Stack; Knowledge Base and Data; System Architecture; Implementation Highlights; Testing and Results; Evaluation and Metrics; Screenshots; Challenges and Learnings; Future Improvements; Conclusion; References and Links.

## Planned experiments
Create a fixed dataset of 20 prompts across four categories:
- Academic learning
- Technical/programming
- Business/productivity
- Creative/content generation

For each prompt, record:
- Original prompt score
- Optimized prompt score
- Original response metrics
- Optimized response metrics
- Improvement percentage
- Failure/edge-case notes

Do not invent results. Populate the final report from actual executions.
